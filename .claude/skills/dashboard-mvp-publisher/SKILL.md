# Что есть в дашборде

**Режим:** MVP с фиктивными данными. Никакого API WB, никаких токенов, всё внутри `index.html`.

**Блоки:**
- 6 KPI-плиток (выручка, заказы, средний чек, возвраты, реклама, прибыль)
- Графики: динамика продаж, реклама, прибыль по товарам, остатки
- Таблица товаров с фильтрами и сортировкой
- Темы: светлая / тёмная
- Период: год / месяц / неделя / день
- Экспорт в CSV

**Палитра:** sproots `#f9f9f9` / `#151515` / `#fbcf02`, Montserrat, радиус 4px.

**Адаптив:** 400–1920px (правила из родительского скилла `dashboard`).

Или двойной клик по `index.html` — для демо этого достаточно.

## 2. Внесение изменений в дашборд

**Алгоритм правки `index.html`:**

1. Прочитай файл целиком (он большой — 1962 строки, ~112 KB).
2. Найди нужный блок по комментарию `<!-- ===== ... ===== -->`.
3. Сделай минимальную правку.
4. Проверь через локальный сервер: `python3 -m http.server 8000`.
5. Сделай скриншот через Playwright, сравни до/после.
6. Если всё ок — коммить и пушь.

**Не делай:**
- Не разбивай `index.html` на части — он должен оставаться одним файлом (правило `dashboards-offline-no-cdn`).
- Не добавляй внешние библиотеки и CDN.
- Не вшивай токены и секреты.

## 3. Обновление README

`README.md` — главная точка входа для посетителей репозитория и пользователей дашборда. Структура:

1. Заголовок и краткое описание (1–2 строки).
2. Что это / что показывает.
3. Особенности (один файл, без CDN, адаптив, демо-данные).
4. Состав репозитория (дерево папок).
5. Запуск (двойной клик).
6. Назначение MVP (без упоминания API/токенов).
7. Скриншоты (из папки `скриншоты/`).
8. Технологии и палитра.
9. Лицензия.

**Не упоминай в README:**
- Режимы доставки данных (CSV/API/хостинг) — этого нет в MVP.
- Получение WB-токена, API-эндпоинты.
- Локальный сервер с прокси — этого в публичном MVP нет.

## 4. Обновление спецификации

`спецификация.md` — описание интерфейса и метрик. Структура:

1. Что это (MVP, демо-данные).
2. Цель MVP.
3. Экраны и блоки (KPI, графики, таблица).
4. Управление (период, фильтры, темы).

6. Технические требования.

`КАК-ПОЛЬЗОВАТЬСЯ.md` — короткая инструкция для конечного пользователя. Только:

## 7. Публикация изменений в GitHub

**Алгоритм:**

1. Проверить статус: `git status`
2. Добавить файлы: `git add <files>` (НЕ добавляй `.env`, `serve.py`, личные файлы).
3. Коммит: `git commit -m "Краткое описание"`
4. Пуш: `git push origin main`
5. GitHub Pages автоматически обновится через 1–2 минуты.

**Если `git` не инициализирован:**

```bash
git init
git branch -M main
git remote add origin https://github.com/ZolotarevMikhail/Dashboard-SPR-MVP.git
git push -u origin main
```

**Если нужна авторизация:**

```bash
gh auth login
# или используй токен через gh: gh auth login --with-token < token.txt
```

Проверить статус: `gh auth status`

# Частые задачи

**Добавить новый график:**
Найти в `index.html` блок `<!-- ===== Charts ===== -->`, добавить новый SVG-рендер. Не забыть про `ResizeObserver`.

**Поменять палитру:**
Найти `:root { --surface-1: ... }` в `<style>`. Палитра sproots — см. memory `sproots-design-palette`.

**Добавить KPI-плитку:**
Найти `<!-- KPI grid -->` или похожий комментарий. Скопировать структуру существующей плитки, изменить данные.

**Обновить README:**
Использовать структуру из раздела 3. Сверяться с актуальным состоянием дашборда.

**Что-то сломалось после правки:**
Откатить: `git checkout HEAD -- index.html`. Посмотреть diff: `git diff HEAD~1 HEAD -- index.html`.
